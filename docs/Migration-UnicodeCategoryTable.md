# Migration — `CharUnicodeInfo::GetUnicodeCategory` answers the whole code space (ticket #2315)

*2026-08-19.* The declared reduction is **gone**. `GetUnicodeCategory` was an ASCII-plus-surrogate
ladder that answered `OtherNotAssigned` for everything else; it now reads a generated Unicode 16.0
table. **292,420 of the 1,114,112 code points changed answer.** Read §2 before upgrading.

Landed under `docs/StandingApprovals.md` **SA-4**, which *is* the Approval F this ticket recorded
as its gate. No signature, layout, vtable or `noexcept` change.

---

## 1. The gate was already lifted

#2315's body says the decision is *"already before the user, worded, as Approval F / ticket
#2018"*, and #2336 and #2338 add *"VERIFIED ABSENT in this container … and `/rv` is absent"*.

Both premises are **stale**. SA-4 was granted 2026-08-17 and is exactly that approval: a source
(`/rv/tmp/runtime`'s `CharUnicodeInfoData.cs`, MIT, already covered by this project's .NET
attribution), an attribution, a stated version (**UCD 16.0**, from
`<UnicodeUcdVersion>16.0</UnicodeUcdVersion>`), and an update policy (pinned until an explicit
bump ticket). The file is present and is 262,598 bytes. SA-4 also fixes the order —
**#2315 → #2336 → #2018 → #2338** — so the three remaining tickets are unblocked too, not merely
this one.

## 2. What changed

| | Was | Is |
|---|---|---|
| every non-ASCII, non-surrogate code point | `OtherNotAssigned` | its real category |
| `U+00C9` É | `OtherNotAssigned` | `UppercaseLetter` |
| `U+0301` combining acute | `OtherNotAssigned` | `NonSpacingMark` |
| `U+2028` | `OtherNotAssigned` | `LineSeparator` |
| `U+E000` | `OtherNotAssigned` | `PrivateUse` |
| `U+1F600` 😀 | `OtherNotAssigned` | `OtherSymbol` |
| 17 ASCII punctuation/symbols | `OtherPunctuation` | six finer categories (§3) |
| letters, digits, controls, `U+0020`, surrogates | — | **unchanged** |
| `U+D7FF`, `U+10FFFF` | `OtherNotAssigned` | **unchanged** — genuinely unassigned |

`System::Char::IsNumber`, `IsSeparator`, `IsLetter` and every other predicate built on the
category move with it. That is the point of the ticket, and it is also the largest behaviour
change in it: code that relied on `IsLetter('é') == false` now sees `true`.

The answer remains **locale-independent** — a table lookup consults no locale facet at all, which
is a stronger guarantee than #2316's ASCII ladder gave, not a weaker one, and the locale tests are
kept.

## 3. Seventeen ASCII code points moved, and #2316 predicted it

#2316 documented that *"every punctuation and symbol character is reported OtherPunctuation rather
than its finer .NET subcategory"* and left it as part of the reduction. Those are exactly the 17
that moved:

| To | Code points |
|---|---|
| `MathSymbol` | `+ < = > \| ~` |
| `OpenPunctuation` | `( [ {` |
| `ClosePunctuation` | `) ] }` |
| `ModifierSymbol` | `^ \`` |
| `CurrencySymbol` | `$` |
| `DashPunctuation` | `-` |
| `ConnectorPunctuation` | `_` |

The ASCII ladder was **deleted, not kept as a fast path**. Keeping it would have been two sources
of truth for the same 128 code points, and it was wrong on 17 of them.

## 4. The table

Generated by `scripts/gen_unicode_tables.py` into
`modules/core/include/System/Globalization/detail/UnicodeCategoryTable.hpp` (136 KiB). Both the
generator and the table are committed, as SA-4 requires; `--check` regenerates and diffs, so the
committed table is verifiable rather than merely present, and a hand edit is caught.

The layout is .NET's own **11:5:4 three-level trie**, copied wholesale rather than re-derived: a
different packing would be a second table to keep correct, and SA-4's point is that there is one
source of record. The lookup in `UnicodeCategoryLookup.hpp` is
`CharUnicodeInfo.GetCategoryCasingTableOffsetNoBoundsChecks` transcribed, including that the
level-2 index is a **byte** offset into a table read as `uint16_t`. The `uint16_t` is assembled
from its bytes rather than `reinterpret_cast`-ed, which is why this is correct on a big-endian
host — .NET calls `ReverseEndianness` at the same place for the same reason.

The simple uppercase/lowercase tables joined the same generated header in #2018 and reuse the
category trie's index arrays. Grapheme-segmentation values remain deliberately unextracted because
that optional subsystem is not ported and no caller would verify them.

## 5. The cross-check SA-4 requires

> "Disagreements between the source of record and either corpus … **every disagreement must be
> listed in the design record** rather than averaged away."

| Corpus | UCD | Disagreements | Assigned in 16.0, unassigned there | **Genuine reclassifications** |
|---|---|---|---|---|
| Python 3.13.5 `unicodedata` | 15.1.0 | 5,186 | 5,185 | **1** |
| Perl 5.40.1 `unicore` | 15.0.0 | 5,813 | 5,812 | **1** |

**The complete list of genuine reclassifications is one code point, and it is the same one in
both corpora:**

* **U+1171E** AHOM CONSONANT SIGN MEDIAL RA — `Mn` (NonSpacingMark) in 15.0 and 15.1, `Mc`
  (SpacingCombiningMark) in 16.0.

Everything else is a code point Unicode assigned after the corpus was cut. The two corpora
**corroborate each other rather than merely both differing**: the 627-code-point gap between the
counts is exactly Unicode 15.1's own additions, which Python has and Perl does not.

The Perl figures come from parsing `unicore/lib/Gc/*.pl`, which are decimal **inversion lists**
(`V<count>` then alternating boundaries) rather than range tables — a first parse that read them as
ranges reported 0 code points covered and 0 disagreements, which is what a silently wrong oracle
looks like.

## 6. External corroboration, not the table agreeing with itself

A count of assigned code points proves nothing if it is compared against itself. The census is
therefore **decomposed**:

```
1,114,112 total − 819,533 Cn                       = 294,579 assigned
294,579 − 137,468 Co − 2,048 Cs − 65 Cc            = 154,998
```

and **154,998 is the number of characters Unicode 16.0 itself publishes**. An all-unassigned
table, an off-by-one level index, or a regeneration against a different UCD all move it.

## 7. Evidence

Five mutations on the trie arithmetic, **all caught** — level-1 shift 9→10, level-2 shift 6→5,
level-3 mask `0x0F`→`0x1F`, category mask `0x1F`→`0x3F`, and the level-2 high byte shifted 16
instead of 8. Each is caught by between six and twelve cases, which is what a whole-code-space
sweep buys over sampling.

Six of #2316's pins are **inverted, not deleted** — each asserted something true of the reduction
this ticket removed. One of them, `U+D7FF == OtherNotAssigned`, was **kept**: it is genuinely
unassigned in UCD 16.0 (Hangul Jamo Extended-B stops at U+D7FB), so #2316's value was right for a
reason it could not have known. A first cut "updated" it to `OtherLetter` and the table said no.

## 8. Downstream, measured

`cna` and `mobile-eggbert` reference `CharUnicodeInfo` or `GetUnicodeCategory` in **zero** places.
Neither was modified. Consumers that call `System::Char` predicates on non-ASCII text will see the
new answers; that is the repair.
