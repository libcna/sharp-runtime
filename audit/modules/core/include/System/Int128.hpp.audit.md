# Audit: `modules/core/include/System/Int128.hpp`

## Metadata

- Audit status: AUDITED (534 lines, header-only implementation, full read).
- Runtime validation: integration `Int128Tests.*` passed 68/68; additional
  `Core.Base` `Int128Tests2.*` and Int128 `BitConverter` filters passed 9/9 on
  2026-07-25.
- Direct probe: compiled with `g++ -std=c++20 -fsanitize=undefined
  -Imodules/core/include /tmp/sharp_runtimervc_int128_audit_probe.cpp`.

## Assessment

The implementation is much more deliberate than a basic `__int128` wrapper:
unchecked add/subtract/multiply and unary negation explicitly use unsigned
arithmetic; division/modulo protect the `MinValue / -1` undefined case; and
shift counts are masked to .NET's modulo-128 behavior.  The integration suite
locks those previously hardened overflow paths.  However, the `MinValue`
decimal boundary was missed in both parsing and formatting, and formatting
diagnostics are inconsistent with the project exception hierarchy.

## SR-AUD-019 — high — `Int128` parsing and decimal formatting of `MinValue` execute signed-overflow UB

Two public paths negate a signed `__int128` whose value is `MinValue`:

- `TryParse("-170141183460469231731687303715884105728", result)` reaches
  `-static_cast<__int128>(val)` when `val == 2^127`;
- `MinValue().ToString()` reaches `-value_` to construct its unsigned decimal
  magnitude.

The sanitizer probe reported both exact source locations:

```
Int128.hpp:234:26: runtime error: negation of 0x80000000000000000000000000000000 cannot be represented in type '__int128'
Int128.hpp:143:72: runtime error: negation of 0x80000000000000000000000000000000 cannot be represented in type '__int128'
parse_min=1
format_min=-170141183460469231731687303715884105728
```

The current compiler happens to print and parse the intended value after
reporting undefined behavior, which is not a correctness guarantee.  This is a
reachable public extreme-value path and is especially notable because nearby
operators already avoid this exact C++ pitfall.

### Required post-audit verification

Derive negative magnitudes entirely in `unsigned __int128` arithmetic and
construct `MinValue` parse bits without signed negation.  Add exact
`Parse`/`TryParse`/`ToString` vectors for `MinValue`, then run them under UBSan
alongside the existing overflow-operator vectors.

## SR-AUD-021 — medium — invalid numeric formats are silently accepted or leak `std` exceptions

`ToString(const std::string&)` treats every format type other than `X`, `x`,
`D`, and `d` as ordinary decimal output.  It also sends the suffix through
`std::stoi` without translating malformed/oversized precision.  The probe
observed:

```
int_format(Q)=42
int_format_exception(Xz)=stoi
int_format_exception(X999999999999999999999)=stoi
```

An unknown numeric standard format must raise `FormatException`, rather than
silently changing the requested format; invalid numeric format syntax must not
escape as a `std::invalid_argument` or `std::out_of_range`.  The corresponding
.NET numeric-format contract lists an unknown single-character specifier as a
runtime `FormatException`:
<https://learn.microsoft.com/en-us/dotnet/standard/base-types/standard-numeric-format-strings>.
`UInt128`, `Int64`, and `UInt64` have the same unknown-format fallback and are
covered by this finding.

### Required post-audit verification

Parse and validate the complete format token before output.  For both 128-bit
types, assert `System::FormatException` for `"Q"`, `"Xz"`, and an
out-of-range precision; retain positive `X`/`x`/`D`/`d`/`G` vectors and
document any intentionally unsupported standard formats.

### Remediated (integer slice) — ticket #1847 (2026-07-30)

The **integer-wrapper slice** is done for all ten wrappers (`Byte`, `SByte`,
`Int16`, `UInt16`, `Int32`, `UInt32`, `Int64`, `UInt64`, `Int128`, `UInt128`):
an unknown format specifier now throws
`System::FormatException("Format specifier was invalid.")` instead of falling
through to decimal, matching .NET (`Number.Formatting.cs`
`ThrowFormatException_BadFormatSpecifier`, `SR.Format_BadFormatSpecifier` =
"Format specifier was invalid."). Two premise corrections were needed:

1. **The 128-bit types lacked an explicit `G`/`g` branch** — they reached
   General format only through the old decimal fallthrough, so replacing the
   fallthrough with a throw would have broken `ToString("G")`. An explicit
   `if (type == 'G' || type == 'g') return ToString();` was added to both before
   the throw (caught by the pre-existing
   `Int128DefinedArithmeticTests.EveryFormatPathThatDelegatesToToStringIsUnchanged`).
2. **The 128-bit width `std::stoi` was itself unguarded** (`Int128.hpp` /
   `UInt128.hpp`), unlike the eight smaller wrappers whose width parse already
   funnels through `FormatException`. Both are now wrapped, so a malformed
   precision (`"Bx"`) throws `FormatException` rather than leaking
   `std::invalid_argument`.

Per-type `ToString_UnknownFormat_Throws` tests added (throw on `"Q"`, no-throw
on `"G"`; plus malformed-precision `"Bx"` for the 128-bit types).

**Float slice NOT closed here.** The finding's `std::stoi`-leak clause for
`Single` (`Single.hpp:607`) and `Double` (`Double.hpp:690`) — whose precision
parse is still unguarded — is the **CCF-006 slice**, deliberately excluded from
CCF-003 (`docs/NumericWrapperBoundaryPlan.md` §4/§13). It is tracked by the new
inactive ticket **#1849** and remains open; do not read "remediated" as covering
`Single`/`Double`.

## Other missing assertions and diagnostics

- The tests do not parse `MinValue`, format it in decimal or hexadecimal, or
  verify a negative value whose lower/upper halves both participate.
- Rotations are checked only at 0/1.  Add 63/64/65/127 and negative counts,
  plus a negative value, to preserve the unsigned bit-pattern conversion.
- `GetHashCode` is only checked for equal values; it should never be used as a
  unique identifier (see SR-AUD-018 for the related test-contract rule).

## Final assessment

The carefully repaired operator layer makes the remaining signed-boundary UB
stand out.  Fix SR-AUD-019 before relying on full-range decimal
serialization/parsing; resolve the shared formatting diagnostics in SR-AUD-021
at the same time.
